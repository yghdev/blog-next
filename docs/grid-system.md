# 栅格系统（Grid System）契约

> 这份文档是**前台与后台共用的版面约定**。它写的每一条都有对应的代码或测试；
> 反过来，代码里改动了这里的东西，这里也要改。
>
> 守约的测试：`tests/grid-system.test.ts`、`tests/layout-tokens.test.ts`、
> `tests/breakpoints.test.ts`（静态），`tests/grid-alignment.mjs`、
> `tests/layout-regression.mjs`（浏览器）。

## 1. 三层模型

| 层 | 管什么 | 谁在用 | 单位 |
|---|---|---|---|
| **整页栅格** | 页面"家具"的落位：留白 / 左导航 / 正文 / 右栏 | `.site-shell`、`.sidebar`、`.toc-col`、页脚 | 12 列 × 24px |
| **内容栅格** | 内容区**内部**的并列块怎么分 | `.stat-grid`、`.fr-grid`、`.conflict-grid` | 12 列 × 各自密度栅距 |
| **纵向节奏** | 块与块、块内元素之间的距离 | 前后台全部规则 | 4px 刻度 `--space-N = N×4px` |

## 2. 前台

### 2.1 整页栅格（1 / 2 / 6 / 2 / 1）

| 令牌 | 值 | 说明 |
|---|---|---|
| `--page-max` | 1552px | 容器上限（列宽 + 11 栅距 + 两侧各一列留白） |
| `--page-gutter` | 24px | 整页栅距 |
| `--page-col` | `calc((min(100%, 1552px) - 11 × 24px) / 12)` | 单列宽；在使用处按百分比基准解析（fixed = 视口宽，页脚 = 包含块宽） |
| `--measure-prose` | 672px | 正文行宽（阅读参数，不随列宽漂移） |

列分配（三栏，≥1392）：

| 列 | 1 | 2–3 | 4–9 | 10–11 | 12 |
|---|---|---|---|---|---|
| 用途 | 留白 | 左导航（fixed，宽 = 2 列 + 1 栅距） | 正文（6 列） | 右栏（2 列） | 留白 |

两栏（821–1391）与宽版页（搜索 / 友链）：右栏那两列并入正文 → **正文 4–11 共 8 列**。

1440 视口实测：留白 122 / 导航 220 / 正文 708 / 右栏 220 / 留白 122；
1552 视口：131 / 239 / 764 / 239 / 131。

### 2.2 为什么必须重定义骨架

旧的 `288 / 800 / 320 + 40 栅距` 无法落在任何等宽列栅格上：

要让三条轨都等于 `k·u − g`（u = 列宽 + 栅距），需
288 = k₁u − g、800 = k₂u − g、320 = k₃u − g 同时成立。
相减得 (k₂−k₁)u = 512、(k₃−k₁)u = 32 → u 必须同时整除 512 与 32；
逐个试 u ∈ {1,2,4,8,16,32}，代入 0 < g < u 均无解。

所以"整页栅格"只能**由列反推轨道**，这也是第一轮失败的根因。

### 2.3 断点

| 断点 | 行为 |
|---|---|
| ≥1392 | 三栏（正文 6 列 + 右栏 2 列） |
| 821–1391 | 两栏（右栏收起，正文 8 列） |
| ≤820 | 单栏（左导航变顶栏 + 抽屉，正文 = 视口 − 40） |

两个跳变是**预期**，登记在 `tests/breakpoints.test.ts`：

- 1391→1392：正文 919 → 684（右栏出现，正文少 2 列）
- 821→820：正文 539 → 780（左导航消失，正文铺满）

区间内都是连续收缩（两栏每 1px 视口最多变 1px），不允许出现别的断崖。

### 2.5 内容栅格（内容区内部）

- 12 列，栅距由 `--grid-gutter` 提供，默认 24px；**允许按密度局部覆盖**：
  `.stat-grid` 8px、`.fr-grid` 10px、`.conflict-grid` 12px。
- 列数写**字面量** `repeat(12, minmax(0, 1fr))`：CSS Grid 的 `repeat()` 不接受 `var()`，
  所以不提供 `--grid-cols` 令牌，由静态测试盯住这个 12。
- 单列阅读区（文章列表 / 正文 / 表单）**不套**内容栅格。

## 3. 后台

后台是**另一套骨架**（侧栏 + 主体），但用**同一套刻度与列契约**。

### 3.1 骨架（整页 12 列，1 / 2 / 8 / 1）

后台与前台**共用同一套列线与令牌**（`--page-max` / `--page-gutter` / `--page-col`）：

| 列 | 1 | 2–3 | 4–11 | 12 |
|---|---|---|---|---|
| 用途 | 留白 | 侧栏（2 列） | 主体（8 列） | 留白 |

- `.admin-shell` = 12 列栅格 + `max-width: var(--page-max)` + `margin: 0 auto`；
- `.admin-sidebar` `grid-column: 2 / span 2`，白底 + 1px 右边界；
- `.admin-body` `grid-column: 4 / span 8`，`.admin-main` 只留内边距（40），不再自己封顶；
- 专注模式（`body.editor-focus-mode`）没有侧栏，主体铺满 12 列。

旧的 `--fx-sidebar-w: 232px` / `--fx-content-max: 1320px` / `--fx-content-max-wide: 1440px`
三个常量已删除 —— 后台宽度是列宽的推论，不是手写值。

后台断点（字面量，媒体查询里不能用 `var()`）：820 / 1080 / 1100 / 1200 / 1600。
≤820 退出整页栅格：侧栏变抽屉，主体自己给 16 / 20 内边距。

### 3.4 内容栅格

- 同一套 12 列 + `--grid-gutter`（叠加层画在 `.admin-shell` 的整页栅格上）。
- 已落地：`.conflict-grid` = 4 + 4 + 4（栅距 12px）。
- 后台的表格（flex 列宽）、媒体库（auto-fill 168px）、概览 5 张统计卡（12 除不尽）

## 5. 验证

### 5.1 看得见栅格：`?grid=1`

- 前台任意页：`/?grid=1` —— **整页** 12 列 + 8px 纵向刻度（含左右留白列）。
- 后台任意页：`/admin/overview?grid=1` —— 与前台同一套整页 12 列（画在 `.admin-shell` 上）。
- ≤820 自动切 4 列。关掉只需去掉 query：不带参数时组件渲染 `null`，
  服务端 HTML 无差异，不影响 nginx 微缓存、SEO 与分享卡。

### 5.2 命令

~~~bash
npm test                       # 静态契约（令牌 / 列分配 / 断点公式 / 叠加层 / 文档）
node tests/layout-regression.mjs   # 14 档视口 × 标准页/宽版页 + 对齐断言
npm run test:grid              # 浏览器：前后台块对齐 + 叠加层开/关零位移
~~~

### 5.3 改布局时的 checklist

1. 先问：这是"家具"（整页栅格）还是"内容区里的并列块"（内容栅格）？
2. 家具用列号（`grid-column`）；fixed 的左导航用 `--page-col` 算 left/width。
3. 内容块等宽 ≤4 列用 `repeat(N, minmax(0,1fr))`；非对称才上 12 列 + span。
4. 栅距：整页 `--page-gutter`；内容块 `--grid-gutter`（可局部覆盖）。
5. 间距一律 `var(--space-*)` / `var(--fx-s*)`，不写字面 px。
6. 改完跑 `npm test`：断点公式与列分配会被逐条断言；
   `layout-regression` 红了通常说明"你在改设计"，先确认是不是有意的。
