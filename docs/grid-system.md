# 栅格系统（Grid System）契约

> 这份文档是**前台与后台共用的版面约定**，不是设计稿说明。
> 它写的每一条都有对应的代码或测试；反过来，代码里改动了这里的东西，
> 这里也要改 —— 否则下一个人只会在 CSS 里看到一堆 12 和 span。
>
> 守约的测试：`tests/grid-system.test.ts`（静态）、`tests/grid-alignment.mjs`（浏览器）。
> 视觉基线：`node tests/layout-regression.mjs` 的 14 档宽度矩阵必须全绿。

## 1. 三层模型

栅格化在这套代码里只做三件事，**不要把它们混成一件**：

| 层 | 管什么 | 谁在用 | 单位 |
|---|---|---|---|
| **骨架栅格** | 页面"家具"之间的轨道：左导航 / 正文 / 右栏 | `.site-shell`、`.admin-shell` | 固定 px 轨道 + 断点 |
| **内容栅格** | 内容区**内部**的并列块怎么分 | `.stat-grid`、`.fr-grid`、`.conflict-grid` | 12 列 × 24px 栅距 |
| **纵向节奏** | 块与块、块内元素之间的距离 | 前后台全部规则 | 4px 刻度 `--space-N = N×4px` |

三条边界：

1. **骨架的 px 是设计决策，不是密码。** `288 / 800 / 320 / 40 / 960 / 672 / 1392 / 820`
   全部有测试钉住（`tests/breakpoints.test.ts`、`layout-regression.mjs` 14 档矩阵）。
   动它们 = 改设计，必须同时改测试与本文档，并说明为什么。
2. **内容栅格只在"同一行里放多块"时启用。** 单列阅读区（文章列表、正文、表单）
   不套 12 列 —— 套了只会得到一个"每行都跨 12 列"的装饰性网格。
3. **纵向节奏只要求"用刻度"，不要求"贴基线"。** 正文行高 `1.8` 是 P0-1 定下的
   阅读参数（17px × 1.8 ≈ 30.6px），强行贴 4px 基线会改行距；中文 + 代码块 + 图片
   混排时严格基线栅格本来就无法成立。详见 §2.4。

## 2. 前台

### 2.1 骨架参数（锁定）

| 令牌 | 值 | 说明 |
|---|---|---|
| `--w-side` | 288px | 左导航固定轨 |
| `--w-main` | 800px | 中栏上限 |
| `--w-toc` | 320px | 右栏 |
| `--gap-col` | 40px | **骨架**栅距 |
| `--w-read` | 960px | 宽版页（搜索 / 友链）正文上限 |
| `--measure-prose` | 672px | 文章页正文行宽 |
| `--sticky-top` | `var(--space-12)` = 48px | 必须等于 `.site-shell` 的 padding-top（同源） |

断点（只有两个，刻意不增加）：

- **≥1392**：三栏（288 + 中栏 + 320）。1392 是三栏最低点，中栏 640 仍可读。
- **821–1391**：两栏（288 + 中栏），右栏收起，入口在右下悬浮胶囊里。
- **≤820**：单栏，左导航换成顶部栏 + 抽屉。

### 2.2 内容栅格

- **12 列**，栅距 `--grid-gutter: 24px`（**不是** `--gap-col`：40 是家具之间的距离）。
- 列数写**字面量** `repeat(12, minmax(0, 1fr))`。CSS Grid 的 `repeat()` 不接受
  `var()`（浏览器实测无效），所以不提供 `--grid-cols` 令牌 —— 与其给一个
  "看起来能改、实际改不动"的令牌，不如让静态测试盯住这个 12。
- 已落地：
  | 选择器 | 分法 | 栅距 |
  |---|---|---|
  | `.stat-grid` / `.stat-cell` | 6 + 6（第 5 格仍占半行） | 8px（`--space-2`） |
  | `.fr-grid` / `.fr-card` | 单列 = span 12；容器 ≥620px = 6 + 6 | 10px（友链密度） |
- 这些转换**逐像素等价**于原来的 `1fr 1fr` / `repeat(2)`：`span 6 + span 6 + 1 个栅距 ≡ 两等分`。
  换的只是表达方式，收益是以后要 8+4、4+4+4 时改一行 span 就够。

### 2.3 新增并列块的配方

1. 先问：真的需要并排吗？（单列阅读区不套栅格）
2. 等宽 N 列 → `display:grid; grid-template-columns: repeat(N, minmax(0,1fr))`，
   N ≤ 4 且是纯等分时**不必**上 12 列。
3. ≥3 块且要**非对称**（8+4 / 5+7 / 2+1）→ 12 列 + `grid-column: span K`。
4. 栅距只写 `gap: var(--grid-gutter)`；密度不同就**局部覆盖** `--grid-gutter`
   （例如 `.fr-grid { --grid-gutter: 10px }`），不要写裸 `gap: 10px`。
5. 窄屏降级：不是把 `grid-template-columns` 改成 `1fr`（12 条轨道还在，会算错），
   而是让子项 `grid-column: 1 / -1`。

### 2.4 为什么不追求严格基线

正文 `--fs-prose: 17px / line-height 1.8` 是 P0-1 按"672px 下约 39 个汉字/行"定的。
贴 4px 基线的最近值是 32px（≈1.882），会把行距从 30.6 拉到 32 —— 这是可见的阅读手感变化，
而收益只是"DevTools 里数字好看"。所以本项目的纵向节奏只承诺两件事：

- **块级间距用刻度令牌**（间距表见 §1），不再新增字面量；
- **叠加层提供 8px 刻度尺**（§5），需要目测时用它量，而不是靠"感觉差一点"。

## 3. 后台

后台是另一套**骨架**（侧栏 + 主体），但用**同一套刻度与列契约**。

### 3.1 骨架参数（锁定）

| 令牌 | 值 | 位置 |
|---|---|---|
| `--fx-sidebar-w` | 232px | `.admin-shell` 第一轨 |
| `--fx-content-max` | 1320px | `.admin-main` 上限 |
| `--fx-content-max-wide` | 1440px | ≥1600 视口时放宽 |

内容区 = 主体宽度 − 左右各 40px（`--fx-s7`）内边距；≤820 时内边距降为 20/16。

后台断点（比前台多，全部是**字面量**，不做令牌化 —— 媒体查询里 `var()` 不可用）：

| 断点 | 意义 |
|---|---|
| 820 | 侧栏 → 顶栏 + 底部抽屉；单列 |
| 1080 | `.overview-grid` / `.quick-capture-card` / 编辑器回到单栏 |
| 1100 | `.stat-grid` 5 列 → 3 列（3+2，避免孤卡） |
| 1200 | 编辑器工作台轨道变化 |
| 1600 | `.admin-main` 上限 1320 → 1440 |

### 3.2 与前台的刻度统一（本轮最重要的变化）

后台原来有一套自己的 4px 刻度 `--fx-s1…s9`，前台则散落字面量 —— **同一个节奏，两份事实来源**。
现在值只在前台 `:root` 定义一次，后台的名字保留为别名（447 处引用一行未改）：

| 后台名 | 值 | 等价的共享刻度 |
|---|---|---|
| `--fx-s1` | 4px | `--space-1` |
| `--fx-s2` | 8px | `--space-2` |
| `--fx-s3` | 12px | `--space-3` |
| `--fx-s4` | 16px | `--space-4` |
| `--fx-s5` | 20px | `--space-5` |
| `--fx-s6` | 28px | `--space-7` |
| `--fx-s7` | 40px | `--space-10` |
| `--fx-s8` | 56px | `--space-14` |
| `--fx-s9` | 72px | `--space-18` |

⚠️ **编号不对应**（`--fx-s6` 是 28px，`--space-6` 是 24px）。这是唯一需要记的一件事，
`tests/grid-system.test.ts` 会逐档断言，抄错一档就红。

### 3.3 内容栅格

- 同一套 12 列 + `--grid-gutter`，画在 `.admin-main` 的**内容盒**里
  （它有内边距，叠加层用 `background-origin/clip: content-box` 收进内容盒）。
- 已落地：`.conflict-grid` / `.conflict-col` = 4 + 4 + 4（栅距 12px = `--fx-s3`）。
- 后台的表（`.ui-table`）是 flex 列宽（由内容与 grow 决定），**不进 12 列**；
  媒体库是 `auto-fill 168px` 的固有网格，同样不进。两者都登记在 §4。

## 4. 例外登记

登记 ≠ 没人管。这里每一条都写清"为什么不动、动了会怎样"，
防止后来者以为它们是漏改。

| 值 / 写法 | 位置 | 为什么不动 |
|---|---|---|
| 18 / 22 | `.post-card` padding | D-1 按"整屏看到 5 张卡"定的密度，改 16/24 会改卡片高度与压缩比（有断言） |
| 14 | `.post-list` gap | 同上（D-1 由 16 收窄到 14，有断言） |
| 10 | `.post-card` 摘要下边距 / 友链栅距 | 视觉密度决策，不是刻度漏改 |
| 62 / 72 | 归档 / 说说 的时间列宽 | 由日期字形反推，且**必须定宽**才不会随日期位数跳动 |
| 18 / 9 / 6 / 5… | 若干组件内微调 | 图标与文字的视觉对齐，非节奏间距 |
| `1fr 1.25fr` | `.overview-grid` | 右栏元素更多，需要更宽；改 5/7 会左右各挪约 20px |
| `0.85fr 1.15fr` | `.quick-capture-card` | 同上；改 5/7 约 7px（列为待批准的可选项） |
| `repeat(5)` | `.stat-grid`（后台） | 12 除不尽；改 4/6 列会改变信息密度 |
| `repeat(auto-fit, minmax(280px,1fr))` | `.visit-cols` | 容器宽度不可预知，固有网格才是对的 |
| `repeat(auto-fill, minmax(168px,1fr))` | 媒体库 | 缩略图尺寸由内容决定 |
| em 轨 `3.2em 3.2em 1.2em 1fr` | 版本 diff 行 | 对齐的是等宽字符，不是布局列 |
| 820 / 1080 / 1100 / 1200 / 1600 | 后台断点 | 媒体查询里不能用令牌；数字本身是"内容宽度反推"的结论 |

## 5. 验证

### 5.1 看得见栅格：`?grid=1`

- 前台任意页：`/?grid=1`、`/p/12?grid=1` …（叠加层画在 `.content` 里）
- 后台任意页：`/admin/overview?grid=1`（画在 `.admin-main` 的内容盒里）
- 打开后：12 列半透明色带 + 8px 纵向刻度；**≤820px 自动切 4 列**（手机 12 列不可读）。
- 关掉：去掉 query 即可。不带参数时组件渲染 `null`、服务端 HTML 无任何差异，
  因此不影响 nginx 微缓存、SEO 与分享卡。
- 实现：`components/GridOverlay.tsx` 在客户端按 `grid=1` 给 `<html>` 打 `data-grid="1"`，
  样式全部挂在 `html[data-grid="1"]` 前缀下（静态测试守着"不许漏前缀"）。

### 5.2 命令

~~~bash
npm test                       # 含 tests/grid-system.test.ts（刻度/别名/12 列/叠加层/文档）
node tests/layout-regression.mjs   # 前台 14 档几何：必须与改前完全一致
npm run test:grid              # 浏览器：前后台对齐体检 + 叠加层开/关零位移
npm run test:admin             # 后台既有回归（侧栏 / 概览 / 组件库）
~~~

### 5.3 加一个新栅格块时的 checklist

1. 单列还是并列？单列 → 不套栅格。
2. 等宽且 ≤4 → `repeat(N, minmax(0,1fr))`；非对称 → 12 列 + span。
3. 栅距 `var(--grid-gutter)`；密度不同只覆盖 `--grid-gutter`。
4. 窄屏降级用 `grid-column: 1 / -1`，不要改 `grid-template-columns`。
5. 间距用 `var(--space-*)` / `var(--fx-s*)`，不写字面 px。
6. 跑 `npm test` 与 `npm run test:grid`；新块若改变了既有几何，
   `layout-regression` 会红 —— 那是"你在改设计"的信号，不是"测试太严"。
