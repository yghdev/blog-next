feat(storage): 自建七牛对象存储图床，不再依赖第三方平台

此前后台图片走本机磁盘，受限于 ECS 出口带宽（实测 400~700KB/s，
4 路并行不聚合）；后来一度借第三方图床，但它的上传 API 永远返回
/file/xxx 而不是 CDN 直链，访客仍要多经一跳 Worker（3~5 秒）。

现在图片直接写七牛对象存储，正文插入的是 CDN 直链（实测 0.17~0.32 秒），
整条链路只有我们自己 + 七牛，没有一个第三方平台。

新增：
- lib/qiniu.ts        零依赖的 S3 兼容客户端（SigV4 自实现）。
                      不用 @aws-sdk/client-s3：那包十几 MB，而我们只用
                      PUT/GET/HEAD/DELETE/List 五个操作。
- lib/storage.ts      存储策略层。配置存 settings 表，AK/SK 用
                      AES-256-GCM 加密（settings 会进每日备份并同步坚果云，
                      明文存密钥等于把七牛账号写进异地备份）。
- app/api/admin/storage 配置读写 + 连接自检（用待保存参数试列对象）。
- components/admin/StoragePanel.tsx + app/admin/storage  后台配置界面。
- 上传/删除/媒体库全部改造：七牛为主，本机磁盘兜底。

关键设计：
- SigV4 用 AWS 官方三组测试向量逐字节校验（tests/qiniu.test.ts），
  签名错一行都过不去。
- 七牛不可用时退回本机磁盘而不是让上传失败，审计里记录 storage 字段。
- endpoint 填错（把 bucket 前缀也粘进去）自动纠正，避免签名 host 拼错。
- SK 永不回填前端；留空表示不修改，避免明文往返。
- 删除先删对象再删记录，反过来会留下看不见的孤儿对象（会产生费用）。
- 错误码翻成人话（SignatureDoesNotMatch / NoSuchBucket 等）。

兼容性：老图仍在本机 /var/www/blog-images，读取走 nginx 直出，
老文章链接不需要迁移；媒体库会标注每张图存在哪一侧。

验证：tsc 0 错误；npm test 136/136（新增 36 条断言，含 3 组 AWS 官方向量）。
